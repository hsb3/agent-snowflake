# Debugging PNG Generation Failure for agent_enhanced

## Problem

When visualizing the `agent_enhanced` graph, PNG generation failed with:
```
✗ Failed to generate PNG: Failed to reach https://mermaid.ink API while trying to render your graph. Status code: 400.
```

## Root Cause

The mermaid.ink API rejected the diagram due to **escaped special characters in node IDs**:

```mermaid
ModelCallLimitMiddleware\2ebefore_model    # \2e = .
ToolCallLimitMiddleware\5bsql_db_query\5d  # \5b = [, \5d = ]
```

These escape sequences are generated by LangGraph when node names contain special characters (`.`, `[`, `]`). The mermaid.ink API returns a 400 error when it encounters these patterns.

## Investigation Steps

### 1. Identified Available Rendering Methods

LangGraph's `draw_mermaid_png()` supports two methods:
- `MermaidDrawMethod.API` (default): Uses mermaid.ink web service
- `MermaidDrawMethod.PYPPETEER`: Renders locally using headless Chrome

### 2. Tested API Method with Retries

```python
png_data = graph_structure.draw_mermaid_png(max_retries=5, retry_delay=2.0)
```

**Result**: Still failed with 400 error (not a transient issue)

### 3. Attempted PYPPETEER Local Rendering

```python
png_data = graph_structure.draw_mermaid_png(draw_method=MermaidDrawMethod.PYPPETEER)
```

**Result**: Failed due to dependency conflicts
```
AttributeError: module 'websockets' has no attribute 'client'
```

**Cause**: `pyppeteer` (v0.0.25) is unmaintained and incompatible with modern `websockets` package

## Why Pyppeteer Failed

1. Downloaded Chromium successfully (84MB)
2. Attempted to launch browser
3. Failed due to `websockets` version incompatibility
4. `pyppeteer` expects older `websockets.client.connect()` API
5. Modern `websockets` has different API structure

## Solution

Accept that PNG generation fails for complex graphs and provide alternatives:

1. **ASCII visualization** (NEW): Auto-generated fallback ✓
   - Immediately viewable in terminal
   - No external dependencies
   - Shows flow diagram and node connections
   - Generated automatically when PNG fails
2. **Mermaid file generation**: Always succeeds ✓
3. **Online viewer**: [mermaid.live](https://mermaid.live/) ✓
4. **VS Code**: Mermaid preview extensions ✓
5. **Simple graphs**: PNG generation works (see `agent_minimal.png`)

## Updated Script Behavior

Modified `visualize_stategraph.py` to:
1. Always generate mermaid file (never fails)
2. Attempt PNG generation with better error handling
3. **Auto-generate ASCII fallback when PNG fails** (NEW)
   - Creates box-and-arrow ASCII art diagram
   - Shows flow diagram with node boxes and connection arrows
   - Lists all node connections with incoming/outgoing edges
   - Provides statistics (node count, edge count, etc.)
   - Immediately viewable without external tools
4. Provide actionable guidance when PNG fails:
   - Link to mermaid.live
   - Point to mermaid file location
   - Point to ASCII visualization file
   - Suggest viewing alternatives

## Recommendations

1. **For users**: Use mermaid.live to view complex diagrams
2. **For developers**: Consider sanitizing node names in LangGraph graphs
3. **For this project**: Keep both PNG and mermaid files in git
4. **For automation**: Accept that some graphs can't be rendered to PNG via mermaid.ink

## Alternative Solutions Considered

1. ✗ **Playwright/Puppeteer**: Similar dependency issues
2. ✗ **Selenium + Chrome**: Too heavyweight for simple visualization
3. ✗ **Modify mermaid diagram**: Would break LangGraph's generated output
4. ✓ **Use mermaid file + online viewer**: Simplest, most reliable
