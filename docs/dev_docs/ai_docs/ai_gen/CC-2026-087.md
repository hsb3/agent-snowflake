## 2. Tricky Items Requiring Decoupling

### 2.1 Dependency Management

**Current Issue**: Single `pyproject.toml` with all dependencies mixed together

**Solution**:
- Create workspace in root `pyproject.toml`:
  ```toml
  [tool.uv.workspace]
  members = ["apps/*", "packages/*"]
  ```
- Each app has its own `pyproject.toml` with only required dependencies:
  - **agent**: `langgraph`, `langchain`, `snowflake-connector-python`, `sqlalchemy`, `fakesnow`, `duckdb`
  - **repl-client**: `httpx`, `rich`, `textual` (no `langgraph` dependency!)
  - **repl-client-graph**: `httpx`, `rich`, `langgraph` (for StateGraph, not for server)
- Use `uv sync --package <app-name>` to install app-specific dependencies
- Shared dev tools (`ruff`, `ty`, `pytest`) can stay in root or be duplicated per-app

**Migration Steps**:
1. Create new `pyproject.toml` in each app directory
2. Move relevant dependencies from root to app-specific files
3. Update root `pyproject.toml` to workspace mode
4. Test `uv sync` in each app directory independently

---

### 2.2 Environment Variables and Configuration

**Current Issue**: Single `.env` file with all config namespaced by app

**Solution**:
- Each app gets its own `.env.example` with only relevant variables:
  - **agent**: `SNOWFLAKE_AGENT_*`, `LANGGRAPH_DEV_SERVER_PORT`, API keys
  - **repl-client**: `LANGGRAPH_DEV_SERVER_URL` (defaults to `http://localhost:2024`)
  - **repl-client-graph**: `LANGGRAPH_DEV_SERVER_URL`
- REPL clients no longer need agent-specific env vars
- Users can still have a root `.env` for local monorepo development

**Migration Steps**:
1. Create `.env.example` per app with only relevant vars
2. Update each app's config loader to look for `.env` in app directory first, then fallback to root
3. Document that REPL clients only need server URL, not agent config

---

### 2.3 Shared Code Between REPL Clients

**Current Issue**: Both REPL clients have similar `core/`, `streaming/`, `ui/` modules but with subtle differences

**Decision Point**: Should we extract shared code to `packages/common/` or accept duplication?

**Recommendation**: **Accept duplication initially**, then refactor if needed
- The two REPL implementations have diverged intentionally (classic vs StateGraph)
- Duplication is acceptable for ~2000 lines of code
- Premature abstraction creates coupling and maintenance burden
- If patterns stabilize, extract to `packages/common/` later

**If Sharing is Needed**:
- Extract truly identical code (e.g., `parsers.py`, `logging.py`) to `packages/common/`
- Both REPLs depend on `common` in their `pyproject.toml`:
  ```toml
  dependencies = ["agent-snowflake-common"]
  ```
- Use relative path dependencies in workspace:
  ```toml
  [tool.uv.sources]
  agent-snowflake-common = { path = "../../packages/common" }
  ```

### 2.4 Test Fixtures and Shared Test Utilities

**Current Issue**: Root `conftest.py` has shared fixtures for all tests

**Solution**:
- Each app gets its own `tests/conftest.py` with app-specific fixtures
- Agent tests need database fixtures → keep in `apps/agent/tests/conftest.py`
- REPL tests need mock server fixtures → keep in respective test directories
- No shared test utilities needed (each app tests independently)

**Migration Steps**:
1. Copy relevant fixtures from root `conftest.py` to each app's `tests/conftest.py`
2. Remove root `conftest.py` or keep minimal version for monorepo-wide tests
3. Ensure each app's tests can run in isolation: `cd apps/agent && uv run pytest`

### 2.5 Makefile Commands

**Current Issue**: Single Makefile with commands for all three apps

**Solution**:
- **Root Makefile** (orchestration only):
  ```makefile
  install-all:
      uv sync

  test-all:
      cd apps/agent && make test
      cd apps/repl-client && make test
      cd apps/repl-client-graph && make test

  format-all:
      uv run ruff format apps/ packages/
  ```

- **Per-app Makefiles** (app-specific):
  - `apps/agent/Makefile`:
    ```makefile
    install:
        uv sync --package agent-snowflake

    setup-chinook:
        uv run python scripts/setup_chinook_db.py

    dev:
        uv run langgraph dev --allow-blocking

    test:
        uv run pytest tests/
    ```

  - `apps/repl-client/Makefile`:
    ```makefile
    install:
        uv sync --package repl-client

    repl:
        uv run python -m repl_client

    test:
        uv run pytest tests/
    ```

**Migration Steps**:
1. Create app-specific Makefiles with focused commands
2. Update root Makefile to orchestrate across apps
3. Remove coupling (e.g., `make repl` in agent should not exist)

### 2.6 LangGraph Server Dependency for REPLs

**Current Issue**: `make repl` starts both server + client, creating tight coupling

**Solution**:
- **Document** that REPL clients require a running LangGraph server (any server, not just agent)
- REPL README should include:
  ```markdown
  ## Prerequisites

  A running LangGraph Dev Server. This can be:
  - The agent from this monorepo: `cd ../agent && make dev-server`
  - Your own LangGraph server on any port
  - A remote LangGraph server (configure `LANGGRAPH_DEV_SERVER_URL`)

  ## Usage

  ```bash
  # Option 1: Use with local agent (from monorepo root)
  cd apps/agent && make dev-server &
  cd apps/repl-client && make repl

  # Option 2: Use with your own server
  export LANGGRAPH_DEV_SERVER_URL=http://your-server:8000
  make repl
  ```
  ```

**Migration Steps**:
1. Remove `make repl` commands that start server + client together
2. Create separate `make repl` (client only) and `make dev-server` (server only) in respective apps
3. Update READMEs to document server prerequisite
4. Add health check to REPL client startup to verify server connectivity

### 2.7 Import Paths

**Current Issue**: Code uses `from src.agent_snowflake...` imports

**Solution**:
- Remove `src/` prefix from imports
- Use proper package installation with `uv sync`
- Each app's `pyproject.toml` defines package location:
  ```toml
  [tool.hatch.build.targets.wheel]
  packages = ["src/agent_snowflake"]
  ```
- Imports become: `from agent_snowflake.graph import build_graph`

**Migration Steps**:
1. No code changes needed if `packages = ["src/..."]` is set correctly in each app's `pyproject.toml`
2. Test imports after restructuring: `cd apps/agent && uv run python -c "from agent_snowflake import graph"`
3. Update `pythonpath` in pytest config if needed

### 2.10 Version Management

**Current Issue**: Single version (`0.1.0`) for entire monorepo

**Solution**:
- Each app gets independent versioning:
  - `apps/agent/pyproject.toml`: `version = "0.1.0"`
  - `apps/repl-client/pyproject.toml`: `version = "0.1.0"`
  - `apps/repl-client-graph/pyproject.toml`: `version = "0.1.0"`
- Root `pyproject.toml` has no version (it's not a package)
- Apps can evolve at different rates (agent v1.0, repl v0.5, etc.)

**Migration Steps**:
1. Set initial version in each app's `pyproject.toml`
2. Document versioning strategy in root README
3. Tag releases per-app: `agent-v0.1.0`, `repl-client-v0.1.0`

### 2.11 CI/CD and GitHub Actions

**Current Issue**: No existing CI, but will need app-specific workflows

**Solution**:
- Create workflow per app in `.github/workflows/`:

  - `repl-client.yml`: Test classic REPL on changes to `apps/repl-client/**`
  - `repl-client-graph.yml`: Test StateGraph REPL on changes to `apps/repl-client-graph/**`
- Use path filters to only run relevant tests:
  ```yaml
  on:
    push:
      paths:
        - 'apps/agent/**'
        - 'packages/common/**'  # If shared code exists
  ```

**Migration Steps**:
1. Create per-app workflows with path filters
2. Each workflow installs only that app's dependencies
3. Root workflow can run all tests for PRs affecting multiple apps

## Summary of Migration Strategy

### Phase 1: Directory Restructuring (Low Risk)
1. Create `apps/` directory structure
2. Move code from `src/` to `apps/*/src/`
3. Move tests to `apps/*/tests/`
4. Move scripts to `apps/*/scripts/`
5. Move docs to `apps/*/docs/`

### Phase 2: Dependency Decoupling (Medium Risk)
1. Create per-app `pyproject.toml` files
2. Set up workspace in root `pyproject.toml`
3. Split dependencies by app
4. Test `uv sync --package <app>` for each app
5. Create per-app `.env.example` files

### Phase 3: Build System Updates (Medium Risk)
1. Create per-app Makefiles
2. Update root Makefile for orchestration
3. Update langgraph.json paths (if needed)
4. Test each app builds/runs independently

### Phase 4: Documentation & Polish (Low Risk)
1. Create per-app READMEs
2. Update CLAUDE.md files
3. Create monorepo overview README
4. Document server prerequisites for REPLs

### Phase 5: Testing & Validation (Critical)
1. Test each app independently:
   ```bash
   cd apps/agent && uv sync --package agent-snowflake && uv run pytest
   cd apps/repl-client && uv sync --package repl-client && uv run pytest
   cd apps/repl-client-graph && uv sync --package repl-client-graph && uv run pytest
   ```
2. Test monorepo-wide: `uv sync && make test-all`
3. Test independent downloads (simulate external user)

## Success Criteria

A user should be able to:

1. **Download just the agent**:
   ```bash
   git clone <repo>
   cd agent-snowflake/apps/agent
   cp .env.example .env
   # Edit .env with API keys and DB connection
   make install
   make setup-chinook
   make dev
   ```

2. **Download just a REPL client**:
   ```bash
   git clone <repo>
   cd agent-snowflake/apps/repl-client
   cp .env.example .env
   # Edit .env with LANGGRAPH_DEV_SERVER_URL
   make install
   # Start their own LangGraph server elsewhere
   make repl
   ```

3. **Work on the full monorepo**:
   ```bash
   git clone <repo>
   cd agent-snowflake
   make install-all
   cd apps/agent && make dev-server &
   cd apps/repl-client && make repl
   ```

Each app should have zero knowledge of sibling apps and work independently.
